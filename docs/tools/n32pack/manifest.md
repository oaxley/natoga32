# n32pack manifest

This page describes the JSON manifest that n32pack reads, every field with its type, default and limits, the `assets.inc` file, and a full example.

The manifest is one JSON object.
An unknown field is an error, and so is any data after the object.
Field names are written in lowercase, as below.
Every path in it is relative to the directory of the manifest (an absolute path is used as it is).

## Game fields

| Field | Type | Required | Default | Rule |
|-------|------|----------|---------|------|
| `name` | string | yes | | Game name, 1 to 32 bytes of valid UTF-8. |
| `version` | string | no | `"1.00"` | `M.mm`: 1 or 2 digits, a dot, 2 digits. Stored in BCD: `"1.00"` is `0x0100`, `"12.34"` is `0x1234`. |
| `min_rom` | string | no | `"0.1"` | `major.minor`: two decimal numbers, each 0 to 255. |
| `regions` | array of strings | yes | | At least one of `"americas"`, `"europe"`, `"asia"`. |
| `languages` | array of strings | no | `[]` | `"english"` is the only value. The array may be empty. |
| `date` | string | no | the time of the run | RFC 3339, for example `"2026-11-18T00:00:00Z"`. Not before `2026-01-01T00:00:00Z`. |
| `graphics_mode` | integer | no | absent | 0 to 3. Absent means the game has no requirement. |
| `rscv` | string | yes | | Path of the `RSCV` chunk file, written by `goasm -f rscv`. |
| `dsym` | string | no | none | Path of the `dSYM` chunk file, written by `goasm --sym`. |
| `entry` | string | no | the first `.text` section | The RISC-V entry point, see below. |
| `assets` | array of objects | no | `[]` | The asset chunks, see [Assets](#assets). |

How the fields reach the cartridge:

| Field | Where it goes |
|-------|---------------|
| `name` | [IHDR](../../console/cartridge/file-format.md#ihdr) game name at `+0x18`, padded with zeros. |
| `version` | IHDR game version at `+0x00`. |
| `min_rom` | IHDR minimum boot ROM version at `+0x02` (major) and `+0x03` (minor). |
| `regions` | IHDR regions at `+0x04`: bit 0 `americas`, bit 1 `europe`, bit 2 `asia`. |
| `languages` | IHDR languages at `+0x06`: bit 0 `english`. |
| `date` | IHDR creation date at `+0x08`: seconds since 2026-01-01 00:00 UTC. |
| `entry` | IHDR RISC-V entry point at `+0x0C`. |
| `graphics_mode` | Flags of the [file header](../../console/cartridge/file-format.md#file-header-16-bytes): the mode in bits 0-2, and bit 3 set. Without the field, the flags are 0. |
| `rscv` | The `RSCV` chunk, copied as it is. |
| `dsym` | The `dSYM` chunk, copied as it is. |

Notes:

- `date`: a time zone offset is accepted: `Z`, or `+hh:mm` / `-hh:mm` with `hh` 00 to 23 and `mm` 00 to 59. Other offsets (`+24:00`, `+0100`) and a date without an offset give `date must be RFC 3339`. A date more than 2^32 - 1 seconds after 2026-01-01 is refused.
  Without `date`, n32pack uses the current time, so two runs do not give the same file.
- The console does not use the version, the minimum ROM version, the languages, the date or the graphics mode.
- `entry` has three forms:
  - absent: the load address of the first `.text` section of the `RSCV` chunk;
  - `"0x…"` (or `"0X…"`): an address in hexadecimal, up to 32 bits;
  - anything else: a label, looked up in the `dSYM` chunk. The `dsym` field is then required.
- The entry point must be 4-byte aligned and inside a `.text` section. A label of another section is refused.

## Assets

Each element of `assets` is an object:

| Field | Type | Required | Default | Rule |
|-------|------|----------|---------|------|
| `name` | string | yes | | `[A-Z][A-Z0-9_]*`, unique in the manifest. It becomes `ASSET_<name>` in `assets.inc`. |
| `type` | string | yes | | One of the 14 asset chunk types: `TILS` `TMAP` `TPAL` `TMAT` `SPRS` `SOAM` `SPAL` `SMAT` `FNTS` `FPAL` `ASMD` `ATMD` `ATFM` `AIFM`. |
| `slot` | integer | no | `0` | 0 to 65535 (u16). |
| `format` | integer | no | `0` | 0 to 255 (u8). |
| `count` | integer | no | `0` | 0 to 65535 (u16). |
| `file` | string | yes | | Path of the payload file. An empty file is allowed. |
| `boot` | boolean | no | `false` | `true` sets the boot flag of the `INDX` entry. |

- The file holds only the payload.
  n32pack writes the 8-byte header (slot, format, count) before it, see [Asset chunks](../../console/cartridge/chunks.md#asset-chunks).
- The meaning of `slot`, `format`, `count` and of the payload is reserved: nothing in the console uses it.
- The asset files are read only when the cartridge is written (`-o`), not for `-inc`.
- The order of the array is the order of the chunks, and it gives the asset ids.

There can be at most 15,871 assets without `dsym`, and 15,870 with it: `INDX` holds 15,872 entries, and `RSCV` and `dSYM` use some of them.

## assets.inc

`-inc` writes one `.equ` line per asset, after one comment line.
The number is the id of the asset in `INDX`: the first asset is 1, because `RSCV` is 0.

```
# assets.inc (generated by n32pack from hello.json, do not edit)
.equ ASSET_LEVEL1_TILES, 1
```

- The comment line has the file name of the manifest as given on the command line, without its directory.
- With no asset, the file only has the comment line.
- The file is plain goasm source: include it with `.include "assets.inc"`.
  The `#` comment and the `.equ` with a decimal number are accepted by goasm, see [Syntax](../goasm/syntax.md#data-directives).
- The ids do not depend on the `dsym` field: `dSYM` comes after the assets.

A game uses the id to find its asset in the index mirror of the console, see [Console view](../../console/cartridge/console-view.md).

## Example

This is the manifest of the sample cartridge, `tests/cartridge/hello.json`:

```json
{
    "name": "Hello",
    "date": "2026-11-18T00:00:00Z",
    "regions": ["americas", "europe", "asia"],
    "languages": ["english"],
    "graphics_mode": 1,
    "rscv": "hello.rscv",
    "dsym": "hello.sym",
    "entry": "main",
    "assets": [
        {
            "name": "LEVEL1_TILES",
            "type": "TILS",
            "slot": 0,
            "format": 4,
            "count": 1,
            "file": "level1.tiles",
            "boot": true
        }
    ]
}
```

- `version` and `min_rom` are absent: the defaults `"1.00"` and `"0.1"` apply.
- `date` is fixed, so the cartridge is always the same bytes.
- `graphics_mode` 1 gives the header flags `0x0009`.
- `entry` is the label `main`, found in `hello.sym`.
- The cartridge has 3 chunks in `INDX`: `RSCV` (id 0), `TILS` (id 1, boot flag) and `dSYM` (id 2).
  The [file format](../../console/cartridge/file-format.md#file-header-16-bytes) page shows the first 16 bytes of the result.

The commands that build it are on the [n32pack](README.md#workflow) page.

## Errors

Some messages, as n32pack prints them (`n32pack: <file>: <message>`):

| Cause | Message |
|-------|---------|
| Unknown field | `json: unknown field "foo"` |
| Name too long or empty | `name must be 1 to 32 bytes of UTF-8` |
| Bad version | `version must look like 1.00` |
| Bad minimum ROM | `min_rom must look like 0.1` |
| No region | `regions: at least one region` |
| Unknown region or language | `regions: unknown region "x"`, `languages: unknown language "x"` |
| Bad date | `date must be RFC 3339`, `date is before 2026-01-01`, `date is too far in the future` |
| Bad graphics mode | `graphics_mode must be 0 to 3` |
| No `rscv` | `rscv is required` |
| Bad asset name | `asset name "x" must match [A-Z][A-Z0-9_]*` |
| Same asset name twice | `duplicate asset name "X"` |
| Unknown asset type | `asset "X": unknown type "Y"` |
| No asset file | `asset "X": file is required` |
| Asset number out of range or not an integer, for example `count` 70000 | `asset "X": count must be an integer from 0 to 65535` (`format`: 0 to 255) |
| Wrong JSON type | `version must be a string`, `regions must be a list of strings`, `assets must be a list of objects`, `asset "X": boot must be true or false`. An asset without a usable name is named by its index: `assets[1]: slot must be ...` |
| Not an object | `the manifest must be a JSON object` |
| Label without `dsym` | `entry "main": no dsym file given` |
| Unknown label | `entry "x": unknown symbol` |
| Bad entry point | `entry 0x... is not 4-byte aligned`, `entry 0x... is not in a .text section` |
