# n32pack - NATOGA32 cartridge packer

`n32pack` builds a NATOGA32 cartridge (`.n32`) from a JSON manifest, the `RSCV` code chunk
and the `dSYM` symbol chunk written by `goasm`, and the asset files. It also writes
`assets.inc`, the asset ids to include in the game's assembly source.

## Building

```bash
cd tools/n32pack
go build -o n32pack .
```

## Usage

```bash
n32pack [-o game.n32] [-inc assets.inc] game.json
```

| Option | Description |
|--------|-------------|
| `-o FILE` | Write the cartridge to `FILE` |
| `-inc FILE` | Write the asset ids to `FILE` |

The flags come before the manifest. At least one of `-o` and `-inc` is required, with exactly
one manifest; otherwise n32pack prints the usage and exits with status 2.
With `-inc` alone, only the manifest is read: the rscv, dsym and asset files may not exist yet.

Errors are printed as `n32pack: <message>` and n32pack exits with status 1. Everything is built
in memory first, so no output file is written when something fails.

## Manifest

The manifest is a JSON object. Unknown fields are an error. Paths are relative to the
manifest's directory.

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `name` | string | required | Game name, 1-32 bytes of UTF-8 |
| `version` | string | `"1.00"` | Game version `M.mm` (1-2 digits, then 2 digits), stored in BCD (`"1.00"` → `0x0100`) |
| `min_rom` | string | `"0.1"` | Minimum ROM version `major.minor`, each 0-255 |
| `regions` | array | required | At least one of `"americas"`, `"europe"`, `"asia"` |
| `languages` | array | `[]` | `"english"`; may be empty |
| `date` | string | now | RFC 3339 date, not before `2026-01-01T00:00:00Z` |
| `graphics_mode` | integer | absent | Required graphics mode, 0-3; absent = no requirement |
| `rscv` | string | required | `RSCV` chunk file (`goasm -f rscv`) |
| `dsym` | string | none | `dSYM` chunk file (`goasm --sym`) |
| `entry` | string | first `.text` | Entry point: a label (looked up in `dsym`, so `dsym` is required) or a `"0x…"` address. Default: load address of the first `.text` section |
| `assets` | array | `[]` | Asset chunks, see below |

Each asset is an object:

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `name` | string | required | `[A-Z][A-Z0-9_]*`, unique; becomes `ASSET_<name>` in `assets.inc` |
| `type` | string | required | `TILS` `TMAP` `TPAL` `TMAT` `SPRS` `SOAM` `SPAL` `SMAT` `FNTS` `FPAL` `ASMD` `ATMD` `ATFM` `AIFM` |
| `slot` | integer | `0` | u16 slot |
| `format` | integer | `0` | u8 format |
| `count` | integer | `0` | u16 count |
| `file` | string | required | Payload file |
| `boot` | boolean | `false` | Set the boot flag of the INDX entry |

The asset file holds only the payload. n32pack writes the 8-byte asset header
(`u16 slot`, `u8 format`, `u8 flags = 0`, `u16 count`, `u16 reserved = 0`) before it.
An empty payload is allowed.

Example `hello.json`:

```json
{
  "name": "Hello",
  "version": "1.00",
  "regions": ["americas", "europe", "asia"],
  "languages": ["english"],
  "rscv": "game.rscv",
  "dsym": "game.sym",
  "entry": "main",
  "assets": [
    {"name": "LEVEL1_TILES", "type": "TILS", "slot": 0, "format": 1, "count": 64, "file": "level1.til"}
  ]
}
```

## Cartridge layout

The chunks are written in this order: `IHDR`, `INDX`, `RSCV` (boot flag set), the assets in
manifest order, `dSYM` (when given), `IEND`. `INDX` lists every chunk between `INDX` and `IEND`;
the id of an entry is its position:

| Id | Chunk |
|----|-------|
| 0 | `RSCV` |
| 1 … n | The assets, in manifest order |
| n + 1 | `dSYM` |

The output is deterministic: the same manifest (with an explicit `date`) and the same input
files give a byte-identical cartridge.

## assets.inc

`-inc` writes one `.equ` per asset, with the asset's INDX id:

```
# assets.inc (generated by n32pack from hello.json, do not edit)
.equ ASSET_LEVEL1_TILES, 1
```

## Workflow

The game source includes `assets.inc`, so it is generated before assembling, and the
cartridge is packed after:

```bash
n32pack -inc assets.inc hello.json            # 1. the asset ids (game.s has .include "assets.inc")
goasm game.s -f rscv -o game.rscv --sym game.sym   # 2. the RSCV and dSYM chunks
n32pack -o hello.n32 hello.json               # 3. the cartridge
```

## Checks

n32pack refuses to build a cartridge when:

- the manifest is not valid JSON, has unknown fields, or a field is missing or out of range
  (name, version, min_rom, regions, languages, date, graphics_mode, asset names and types);
- an asset name is duplicated;
- the `rscv` or `dsym` file is not a complete chunk of the right type (length, CRC);
- an `RSCV` section has an unknown kind, non-zero reserved fields, runs past the chunk,
  is outside its region (`.bss` `0x01000000-0x01200000`, `.rodata` `0x01200000-0x01400000`,
  `.data` `0x01400000-0x01A00000`, `.text` `0x01A00000-0x02000000`) or overlaps another section;
  there must be a `.text` section;
- the `dSYM` data is malformed (bad kind, empty name, duplicate symbol, trailing bytes);
- the entry point is an unknown label, is not 4-byte aligned or is not inside a `.text` section;
- the date is before 2026-01-01 or too far in the future;
- an asset file can't be read;
- there are more than 15,872 INDX entries or the cartridge is over 256 MiB.
